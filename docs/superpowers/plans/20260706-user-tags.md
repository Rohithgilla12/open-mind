# User Tags & Tag Provenance Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development. Steps use `- [ ]` tracking.

**Goal:** User/imported tags that survive enrichment + are searchable; manual tag editing on the detail page; import tag preservation. Spec: `docs/superpowers/specs/20260706-user-tags-design.md`.

**Architecture:** New `items.user_tags text[]` column (AI `tags` stays separate); `search_tsv` rebuilt to index both; `PATCH /items/{id}{userTags}` + `SetUserTags`; importer captures tags → user_tags; detail-page tag editor. Union of the two is displayed/searched.

## Global Constraints

- `tags` = AI (overwritten by enrichment, unchanged behaviour). `user_tags` = user/imported (never touched by enrichment). Display/search = deduped union.
- Tag canonicalisation (shared helper): trim, lowercase, drop empties, dedupe, cap 30 tags, each ≤50 runes. Applied to both manual PATCH and imported tags.
- Every query user-scoped (PATCH/SetUserTags → 404 cross-tenant/missing). Generated code never hand-edited; errors `%w`; no banner comments. `go test -p 1 ./... && golangci-lint run ./...` + web `pnpm turbo run build lint --filter=web` green. Tokens-only web. Commit per task.
- The `search_tsv` rebuild migration must apply cleanly on a populated DB (drop+recreate the STORED generated column and its gin index) — test it.

### Task 3: Import tag preservation
