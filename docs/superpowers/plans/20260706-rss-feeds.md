# RSS/Atom Feed Subscriptions Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development. Steps use `- [ ]` tracking.

**Goal:** Subscribe to RSS/Atom feeds — add → backfill current entries as items + periodic poll for new ones. Spec: `docs/superpowers/specs/20260706-rss-feeds-design.md`.

**Architecture:** New `internal/feeds` (stdlib XML parser + service), `feeds` table, `/feeds` API, a River periodic `poll_feeds` job, and a web `/feeds` page. Reuses `enrich.SafeHTTPClient` (SSRF-safe) and the `internal/importer` dedup/item-create pattern.

## Global Constraints

- No new dependency (stdlib `encoding/xml` only) — matches `internal/importer`'s dependency-free ethos. No new required infra (River periodic jobs run in the existing worker).
- All feed fetches via `enrich.SafeHTTPClient(timeout)` (private-IP guard, redirect cap, size limit). Feed URLs are user-supplied → SSRF surface; never fetch with a bare client.
- Every query user-scoped; entries dedup against existing item URLs (user-scoped) so re-poll/re-add never double-saves. A broken feed sets `last_status` and never breaks the poll loop or a request beyond its own 502-on-add.
- Entries → normal article items (url = entry link, `body`/`note` empty) enqueued via the existing `jobs.EnrichArgs` path. Capture stays instant; enrichment async.
- Generated code never hand-edited; errors `%w`; no banner comments. `go test -p 1 ./... && golangci-lint run ./...` green (CI uses go vet, but local gate is golangci-lint). Web `pnpm turbo run build lint --filter=web` green. Tokens-only web styling. Commit per task.

**Interfaces:** `type Feed struct{ Title, SiteURL string; Entries []Entry }`, `type Entry struct{ URL, Title string }`; `func Parse(data []byte, baseURL string) (Feed, error)`.

- [ ] Step 1 (TDD): fixtures + tests — a minimal **RSS 2.0** doc (`<rss version="2.0"><channel><title>…<link>…<item><title>…<link>…`) → Feed with title/siteURL + entries; a minimal **Atom** doc (`<feed><title>…<link href rel="alternate">…<entry><title>…<link href="…">`) → entries from `link[rel=alternate]` (or first link); a **relative entry link** resolved against baseURL/siteURL; an entry with **no http(s) link** skipped; **malformed XML** → error; empty → error. Bounds/format errors → wrapped error.

### Task 2: Schema + store + feed service

**Files:** `apps/api/internal/store/migrations/0005_feeds.sql`, `apps/api/internal/store/queries/feeds.sql` (+ regen), `apps/api/internal/feeds/service.go`, `apps/api/internal/feeds/service_test.go`

**Interfaces:**
- Migration: `feeds` table per spec (+ `unique(user_id,url)`, `index(user_id)`).
- sqlc: `CreateFeed`, `ListFeeds(user_id)`, `GetFeed(user_id,id)`, `DeleteFeed(user_id,id) :execrows`, `SetFeedPolled(user_id,id,last_polled_at,last_status)`, `ListFeedsDue(older_than)` (last_polled_at is null OR < older_than — note: this one is cross-user, justified: the periodic poller runs system-wide; it still writes items under each feed's user_id), `ListItemURLs(user_id)` (already exists from importer — reuse). All user-facing queries user-scoped.
- `feeds.Service{ Store *store.Store; HTTPClient *http.Client; River *river.Client[pgx.Tx] }` with:
  - `NewService(store, riverClient) *Service` (HTTPClient defaults to `enrich.SafeHTTPClient(20s)`).
  - `Add(ctx, userID uuid.UUID, feedURL string) (db.Feed, int, error)` — validate http(s); dupe → `ErrAlreadySubscribed`; fetch+parse; insert feed row; backfill via `saveEntries`; return feed + added count. Fetch/parse failure → error (handler maps 502), feed NOT persisted.
  - `Refresh(ctx, feed db.Feed) (int, error)` — fetch+parse+`saveEntries`; set last_polled/last_status ("ok" or "error: <short>"); returns new count; internal fetch/parse errors are recorded and returned as (0, nil)-with-status, never fatal.
  - `RefreshDue(ctx, olderThan time.Duration) error` — `ListFeedsDue` → `Refresh` each (continue on individual errors).
  - private `saveEntries(ctx, userID, entries) (int, error)` — load existing item URLs (set), skip dupes + within-batch dupes, cap 100, create pending article item (`CreateItem` url=entry link, body="") + `River.Insert(EnrichArgs)`; best-effort enqueue (log, don't fail the save).
- Sentinel `ErrAlreadySubscribed`.

- [ ] Step 1: migration + sqlc queries; regen; `store.Migrate` embed picks up 0005.
- [ ] Step 2 (TDD, DB-backed, testStore pattern): `TestFeedServiceAddBackfillsAndDedups` (add a feed served by an httptest server returning RSS with 3 entries → feed row + 3 pending items + 3 enrich jobs; one entry URL pre-existing → only 2 new); `TestFeedServiceAddDuplicate` (second Add same url → ErrAlreadySubscribed); `TestFeedRefreshOnlyNewEntries` (Refresh with the same feed → 0 new; feed serves +1 entry → 1 new); `TestFeedRefreshRecordsErrorStatus` (httptest returns 500 → Refresh sets last_status "error: …", no throw, 0 new). Use `enrich`'s httptest style; inject the httptest client via `Service.HTTPClient`.
- [ ] Step 3: implement; `go test -p 1 ./... && golangci-lint run ./...` green; commit `feat(feeds): schema, store queries, subscription service (add/backfill/refresh)`.
