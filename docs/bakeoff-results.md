## Raw observations

Not scored (scoring is done separately). Just the obvious patterns from this run.

- **Long-form articles (paulgraham, danluu, samaltman):** all three extractors succeed with near-identical body lengths and clean title/body. trafilatura and readability produce plain text; jina emits markdown (inline image tags, link syntax) so its body is noisier and slightly longer. readability is consistently the fastest.
- **Dead / moved corpus URLs:** several picks return HTTP errors for the fetch-based extractors — `jvns.ca` ssh-agent post (404), `seriouseats` tomato sauce (404), `budgetbytes` creamy-tuscan-chicken (404), `cooking.nytimes` no-knead-bread (404), `x.com/paulg/...` (404), `unsplash` photo (401). trafilatura and readability correctly surface these as errors; **jina silently returns the site's 404/"Page Not Found" page as if it were content** (e.g. title "Page Not Found", "404"). That is a notable failure mode — jina masks dead links.
- **JS-heavy / SPA pages (apple iphone, linear.app/method):** trafilatura and readability get the correct title and a short meta-description-level body but miss most rendered content; jina renders the SPA and returns far more text (apple 122k chars, linear 3.5k) but heavily polluted with nav/menu boilerplate.
- **Tweets (x.com):** static fetch cannot get the tweet content — naval's tweet yields only the title line + engagement counts (trafilatura) or the login wall (readability/jina). No extractor recovers real tweet text without an API; jina again turns a 404 into fake content for the paulg URL.
- **YouTube:** all three get the video title from metadata. readability returns an empty body (0 chars); trafilatura returns only the footer boilerplate; jina returns rendered page chrome. None extracts a useful description/transcript.
- **Product (amazon):** amazon serves an anti-bot "Continue shopping" interstitial to all three — no real product data extracted. apple product page: trafilatura/readability get the lead image (`Image: y`), jina does not.
- **Image posts (flickr album):** all three get the album title; jina lists album names in the body. Lead image not detected by any.
- **Lead image detection:** only trafilatura and readability populate `LeadImageURL` (from og:image / article image); jina never set it in this run because its `images` map is embedded in the markdown body rather than surfaced structurally for these pages.
- **Latency:** readability fastest (typically 250-900ms), trafilatura mid (~0.5-1.6s), jina slowest (1-8s) due to the remote render round-trip.

Overall shape: trafilatura and readability behave almost identically on clean articles (readability faster), both fail loudly on dead/blocked URLs (good), and both under-extract JS-rendered pages. jina extracts more from SPAs but is noisier, slower, sets no lead image here, and dangerously returns error pages as content.
